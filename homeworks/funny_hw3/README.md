Проверка программы:

```bash
python3 src/main.py check --file samples/ok_sum.funny         
python3 src/main.py check --file samples/bad_types.funny      
python3 src/main.py check "function f(x: int) returns r: int { r = x; }"
python3 src/main.py check --file samples/ok_sum.funny --json   # аннотированный AST (JSON)
python3 src/main.py ast --file samples/ok_sum.funny --json     # неаннотированный AST (HW2)
```

Диагностика (`SEMANTIC ERROR [строка:столбец]: сообщение`, а также `PARSE
ERROR`/`LEXER ERROR`) печатается в **stderr**, а в stdout остаётся только
результат: так `--json` всегда выдаёт чистый JSON. Код возврата 0 при
отсутствии ошибок, 1 при их наличии. Если есть синтаксические ошибки,
семантическая проверка пропускается (AST неполный, ошибки типов на нём были
бы ложными).


## Поддерживаемые типы

| Тип | Где встречается |
|---|---|
| `int` | параметры, возвраты, локальные, выражения |
| `int[]` | параметры, возвраты, локальные, выражения (одномерные массивы) |
| `bool` | **только тип выражений** (условия, предикаты); переменных типа `bool` в Funny нет, присвоить `bool` переменной нельзя |
| `<error>` | служебный: «ошибка уже сообщена», совместим со всем, гасит каскад сообщений |

`string` и `func` в Funny отсутствуют. Приведений и перегрузок нет: типы
должны совпадать точно.

## Правила типизации выражений

| Выражение | Правило | Тип результата |
|---|---|---|
| число | | `int` |
| `true`, `false` | | `bool` |
| переменная | должна быть объявлена и видна в этой области; для локальной без аннотации тип должен быть уже выведен | тип переменной |
| `a[i]` | `a: int[]`, `i: int` | `int` |
| `-e` | `e: int` | `int` |
| `e1 + - * / e2` | оба `int` | `int` |
| `e1 == != >= <= > < e2` | оба `int` | `bool` |
| `not e` | `e: bool` | `bool` |
| `e1 and or -> e2` | оба `bool` | `bool` |
| `f(e1,...,en)` (функция) | `f` определена; число и типы аргументов совпадают с параметрами; функция возвращает ровно одно значение | тип возврата |
| `length(a)` | `a: int[]` | `int` |
| `p(e1,...,en)` (формула) | как у функции; **только в предикатах** | `bool` |
| `forall/exists(x: T \| e)` | `e: bool`; **только в предикатах**; имя `x` уникально в области | `bool` |

«Предикат» это: `requires`, `ensures`, `invariant`, `assert`, `assume`, тело
формулы. Условия `if`/`while`, аргументы, индексы и арифметика предикатом не
являются: кванторы и формулы там запрещены.

## Правила для операторов

| Оператор | Проверка |
|---|---|
| `x = e;` | цель существует и не параметр; тип `e` равен типу `x` (или выводит тип `x`, см. ниже); `e` не `bool` |
| `a[i] = v;` | `a` существует, не параметр, имеет тип `int[]` (или выводится как `int[]`); `i: int`, `v: int`; двумерная индексация запрещена |
| `x, y = f(...);` | `f` функция (не формула); число переменных равно числу возвращаемых значений; типы по позициям совпадают; имена слева не повторяются |
| `if (c) ...`, `while (c) ...` | `c: bool` |
| `invariant p`, `assert p`, `assume p` | `p: bool` |
| `requires`, `ensures` | `bool` |

## Таблицы символов и области видимости

* **Модуль:** функции и формулы (общее пространство имён, имена уникальны).
  Сигнатуры собираются первым проходом, поэтому вызов функции, определённой
  ниже, и взаимная рекурсия допустимы.
* **Функция:** параметры, возвраты, локальные (`uses`), имена уникальны в
  пределах функции.
* **Что видно где** (по спецификации): `requires`: параметры; `ensures`:
  параметры и возвраты; тело, `invariant`, `assert`, `assume`: параметры,
  возвраты, локальные.
* **Квантор:** вложенная область, переменная видна только в теле квантора и
  не может совпадать с именем, видимым в этой области.
* **Параметры (в том числе массивы) только для чтения:** присваивание им и
  `a[i] = v` для параметра-массива запрещено.

## Вывод типов локальных переменных 

Локальная `uses t` без аннотации получает неизвестный тип (`TypeVar`).
Тип **унифицируется** с типом первого присваивания (`t = e;`, кортеж
`t, u = f(...)`, а также `t[i] = v;` задаёт `t: int[]`. Последующие присваивания проверяются против выведенного типа,
конфликт даёт ошибку с указанием, где тип был выведен. Ошибки:

* чтение переменной до первого присваивания (`r = t; t = x;`);
* противоречие (`t = 1; t = a;` для `a: int[]`);
* вывод невозможен: переменной нигде не присваивается значение;
* присваивается значение типа `bool`.

Правая часть присваивания вычисляется **до** вывода типа цели, поэтому
`x = x + 1` для непроинициализированной `x` это ошибка чтения, а не самовывод.

## Формат аннотированного AST

Тот же JSON, что и в HW2 (`{"node": "ИмяКласса", ...}`), плюс:

* **`ty`** у каждого узла-выражения (`Var`, `IntLiteral`, `BoolLiteral`,
  `ArrayAccess`, `Call`, `UnaryOp`, `BinOp`, `Quantifier`): `"int"`,
  `"int[]"`, `"bool"` или `"<error>"`. У `Call` в присваивании кортежа
  `x, y = f(...)` это строка вида `"(int, int[])"`.
* **`ty`** у `LocalVarDef`: итоговый тип локальной (заявленный или выведенный),
  при этом поле `type` остаётся таким, как в исходнике (`null`, если
  аннотации не было).
* **`symbols`** у `FunctionDef` и `FormulaDef`: таблица символов, список
  `{"name", "kind" (param|return|local), "type", "declared", "pos"}`;
  `declared: false` означает, что тип выведен.

Аннотации включаются флагом `with_types` в `ast_nodes.to_dict`; по умолчанию
они не выводятся, поэтому снапшоты парсера HW2 не меняются. Позиции (`pos`)
это смещения от начала текста (как `Token.start`).

## Диагностика

Каждое сообщение содержит позицию и описание, пример:

```
SEMANTIC ERROR [8:9]: несовместимые типы: переменная 't' имеет тип int (тип выведен из первого присваивания в 7:9), а присваивается значение типа int[]
```

Проверка **не останавливается на первой ошибке**: тип `<error>` совместим со
всем, поэтому уже сообщённая ошибка не порождает цепочку повторных. Ошибки
выводятся в порядке позиций.

## Тесты

`tests/semantic_tests.json`, три вида (поле `kind`):

* **`ok`** (13): программа без ошибок; необязательно `expected_locals`
  (проверка выведенных типов локальных);
* **`annotated`** (2): снапшот аннотированного AST (с типами, без `pos`);
* **`error`** (41): `expected_errors`: для каждой ошибки точные `line`,
  `col` и подстрока сообщения; число ошибок должно совпасть.

Негативные тесты покрывают: неизвестные имена и функции, повторные
объявления (функции, параметры, локальные), присваивание параметрам,
несовместимые типы, условия не `bool`, арифметику и сравнение массивов,
неверное число и тип аргументов, формулы и кванторы вне предикатов,
многозначные функции в выражении, ошибки кортежного присваивания,
индексацию (не массив, не `int`, двумерную), `bool` в переменную,
противоречие и невозможность вывода типа, чтение до присваивания, области
видимости `requires`/`ensures`, затенение переменной квантора, несколько
независимых ошибок в одной программе.
