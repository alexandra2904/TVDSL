# Формат IR Funny (HW4)

Трёхадресный код, организованный в базовые блоки. Формат рассчитан на
дальнейшую трансляцию в байт-код JVM.

## 1. Программа и функция

Программа это список функций. Формулы, а также `requires`, `ensures`,
`invariant`, `assert`, `assume` и кванторы в IR **не попадают**: это
спецификации для верификации, у них нет исполняемой семантики.

Функция:

| Поле | Содержание |
|---|---|
| `name` | имя |
| `params` | параметры `(имя, тип)` в порядке объявления |
| `returns` | возвращаемые переменные `(имя, тип)` в порядке объявления |
| `locals` | локальные переменные программы (`uses`) `(имя, тип)` с итоговым типом из HW3 |
| `temps` | временные `%tN` с типами; перечислены только реально используемые |
| `blocks` | базовые блоки; **первый блок это вход** (метка `entry`) |

Имена переменных программы уникальны в пределах функции (гарантия HW3).
Временные всегда начинаются с `%` (идентификатор Funny такого символа
содержать не может, конфликтов с переменными нет).

## 2. Типы и значения

| Тип | Значение |
|---|---|
| `int` | 32-битное целое со знаком, переполнение по модулю 2^32 |
| `int[]` | массив `int`, длина фиксирована; ссылочный тип |

Логические значения это `int`: `0` ложь, любое `!= 0` истина (результаты
сравнений и `not` всегда `0` или `1`). Отдельного типа `bool` в IR нет.

**Операнд** это имя (переменная или временная) либо целая константа.
Константы есть только у `int`.

## 3. Инструкции

| Текст | JSON `op` | Семантика | Типы |
|---|---|---|---|
| `x = a` | `mov` | присвоить | `x, a: int` |
| `x = copy a` | `copy` | **копия** массива (присваивание массива в Funny копирует) | `x, a: int[]` |
| `x = a + b` (`- * /`) | `bin`, `operator` | арифметика; `/` отбрасывает дробную часть (как `idiv`), деление на ноль это ошибка времени выполнения | `int` |
| `x = a < b` (`== != <= > >=`) | `bin`, `operator` | сравнение, результат `0`/`1` | операнды `int`, `x: int` |
| `x = -a` | `neg` | отрицание | `int` |
| `x = not a` | `not` | `1`, если `a == 0`, иначе `0` | `int` |
| `x = a[i]` | `aload` | чтение элемента; выход за границы это ошибка времени выполнения | `a: int[]`, `i, x: int` |
| `a[i] = v` | `astore` | запись элемента на месте; `dsts = [a]`, `args = [a, i, v]` | `a: int[]`, `i, v: int` |
| `x = length a` | `len` | длина массива | `a: int[]`, `x: int` |
| `x = call f(a, b)` | `call` | вызов; аргументы передаются по значению | типы по сигнатуре `f` |
| `x, y = call f(a)` | `call` | вызов с несколькими результатами (`dsts` несколько) | типы по сигнатуре `f` |
| `jump L` | `jump` | безусловный переход | |
| `br c, Lt, Lf` | `br` | если `c != 0` перейти в `Lt`, иначе в `Lf` | `c: int` |
| `ret r1, r2` | `ret` | вернуть значения; число и типы как в `returns` функции | |

Замечания:

* В Funny нет оператора `return`: результат функции это значения
  `returns`-переменных на момент выхода. Генератор всегда кончает функцию
  инструкцией `ret` со всеми возвращаемыми переменными; после оптимизаций
  в `ret` могут стоять константы.
* Параметры доступны только для чтения (гарантия HW3), поэтому массив-параметр
  можно передавать и читать без копирования. Запись `a[i] = v` всегда идёт в
  переменную, которой владеет функция (после `copy` или результата вызова).
* Значение неинициализированной переменной не определено; интерпретатор
  принимает `0` и пустой массив.
* Конъюнкция, дизъюнкция и импликация (`and`, `or`, `->`) компилируются в
  переходы с **ленивым** вычислением правой части; отдельных
  логических инструкций в IR нет.

## 4. Базовые блоки и CFG

* Блок имеет уникальную в функции метку (`entry`, `L1`, `L2`, ...).
* Блок непуст, **заканчивается ровно одним терминатором** (`jump`, `br`,
  `ret`) и не содержит терминаторов внутри.
* Переходы между блоками явные (проваливания нет).
* Рёбра CFG задаются терминатором: `jump L` даёт одно ребро, `br c, Lt, Lf`
  два, `ret` ни одного. В JSON у блока есть готовое поле `succs`.

## 5. Текстовый вид

```
function demo(x: int) returns (r: int)
  locals: a: int, b: int, dead: int
  temps: %t2: int, %t3: int
entry:    ; -> (выход)
    %t2 = x
    %t3 = %t2 + 14
    r = %t3
    ret r
```

После метки стоит комментарий `; -> L2, L3` со списком следующих блоков.

## 6. JSON-формат

Команда `ir --json` (и файл `output/ir/NAME/ir.json`) выдаёт объект с ключами
`optimizations`, `before`, `after`, `metrics`, `coloring`:

```json
{
  "optimizations": ["constprop", "algebra", "dce"],
  "before": { "functions": [ ... ] },
  "after":  { "functions": [ ... ] },
  "metrics":  { "before": {"demo": {"blocks": 1, "instrs": 10, "temps": 4, "colors": 1}}, "after": {...} },
  "coloring": { "before": {"poly": {"graph": {"%t1": ["%t2"]}, "colors": {"%t1": 0, "%t2": 1}, "color_count": 2}}, "after": {...} }
}
```

Функция в `before`/`after` (фрагмент реального вывода для `demo` после
оптимизаций):

```json
{
  "name": "demo",
  "params":  [{"name": "x", "type": "int"}],
  "returns": [{"name": "r", "type": "int"}],
  "temps":   [{"name": "%t2", "type": "int"}, {"name": "%t3", "type": "int"}],
  "blocks": [
    {
      "label": "entry",
      "instrs": [
        {"op": "mov", "dsts": ["%t2"], "args": ["x"]},
        {"op": "bin", "dsts": ["%t3"], "args": ["%t2", 14], "operator": "+"},
        {"op": "mov", "dsts": ["r"], "args": ["%t3"]},
        {"op": "ret", "args": ["r"]}
      ],
      "succs": []
    }
  ]
}
```

Поля инструкции: `op` (всегда), `dsts` (определяемые имена), `args`
(операнды: строка для имени, число для константы), `operator` (у `bin`),
`callee` (у `call`), `targets` (метки у `jump`/`br`). Пустые поля опускаются.
У функции также есть `locals` (в примере опущено для краткости).

## 7. Раскраска временных для кодогенерации

`coloring.<stage>.<функция>.colors` сопоставляет каждой временной номер цвета.
Две временные с одним цветом никогда не живы одновременно, поэтому могут
занимать один и тот же слот локальной переменной JVM. Временные разных типов
(`int` и `int[]`) цвет не делят, так как слоты JVM типизированы. Переменные
программы (`params`, `returns`, `locals`) в раскраске не участвуют и получают
собственные слоты.

Рекомендуемое отображение в JVM:

| IR | JVM |
|---|---|
| `mov` с константой / именем | `iconst`/`bipush`/`ldc` + `iload` и `istore` |
| `bin + - * /` | `iadd isub imul idiv` (семантика совпадает: 32 бита, `idiv` к нулю, ArithmeticException при делении на ноль) |
| `bin` сравнения, `not` | `if_icmpXX` / `ifeq` с переходом, либо цепочка `iconst_0/1` |
| `neg` | `ineg` |
| `aload` / `astore` | `iaload` / `iastore` (ArrayIndexOutOfBoundsException за границами) |
| `len` | `arraylength` |
| `copy` | `clone()` или `Arrays.copyOf` |
| `br c, Lt, Lf` | `iload c; ifne Lt; goto Lf` |
| `call` с одним результатом | `invokestatic`; результат в `istore`/`astore` |
| `call` с несколькими результатами | возврат объекта-кортежа или массива и распаковка |
| `ret` | `ireturn`/`areturn`, при нескольких значениях упаковка как выше |

## 8. API (Python)

| Функция | Назначение |
|---|---|
| `pipeline.front_end(text, lexer)` | текст -> (аннотированный модуль, ошибки) |
| `pipeline.build_ir(module)` | аннотированный AST -> `IRProgram` с блоками (до оптимизаций) |
| `optimize.optimize_program(program, enabled)` | оптимизированная копия; `enabled` это подмножество `{"constprop", "algebra", "dce"}` |
| `optimize.parse_opt_spec("all"\|"none"\|"a,b")` | разбор флагов |
| `regalloc.analyze(fn)` | (граф конфликтов, раскраска, число цветов) |
| `ir.program_to_dict(program)` | JSON-совместимое представление |
| `validate.validate_program(program)` | проверка структуры и типов IR (пустой список = корректно) |
| `interp.run_function(program, name, args)` | выполнение (для проверки корректности) |
