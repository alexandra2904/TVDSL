# HW4. Промежуточное представление и базовые оптимизации (Funny)

Из аннотированного AST (HW3) строится трёхадресный код (IR), затем граф потока
управления (CFG) с базовыми блоками, локальные оптимизации, граф конфликтов
временных по живости и их жадная раскраска.

## Запуск

```bash
cd funny_hw4
python3 src/main.py build        # автомат лексера (HW1) -> output/
python3 src/main.py all          # все наборы: лексер, парсер, семантика, IR
```

IR, оптимизации, метрики:

```bash
python3 src/main.py ir --file samples/opt_demo.funny                 # IR до и после, метрики
python3 src/main.py ir --file samples/opt_demo.funny --graph         # + граф конфликтов и раскраска
python3 src/main.py ir --file samples/opt_demo.funny --json          # всё в JSON

python3 src/main.py ir "function f(x: int) returns r: int { r = x * 1 + 0; }"
```

Проверка «до/после» на конкретных входах (аргументы это элементы JSON-списка;
если первый аргумент отрицательный, писать через `=`):

```bash
python3 src/main.py run --file samples/arrays_calls.funny --func useDivmod --args 17,5
python3 src/main.py run --file samples/arrays_calls.funny --func useDivmod --args=-17,5
python3 src/main.py run --file samples/arrays_calls.funny --func sumSq --args "[1,2,3]"
```

```bash
dot -Tpng output/ir/opt_demo/poly.interference.after.dot -o poly.png
```

## Флаги оптимизаций

Оптимизации включаются и выключаются отдельно параметром `--opt`:

| Значение | Что включено |
|---|---|
| `all` (по умолчанию) | `constprop`, `algebra`, `dce` |
| `none` | ничего: «после» совпадает с «до» |
| `constprop,dce` (любой список) | перечисленные проходы |

| Проход | Что делает |
|---|---|
| `constprop` | распространение констант внутри блока, свёртка операций над константами (с арифметикой 32 бита), `br` с константным условием становится `jump` |
| `algebra` | `x+0`, `0+x`, `x-0`, `x*1`, `x*0`, `x/1`, `0-x` (в `-x`), `x-x`, `x==x`, `x<x` и т.п., удаление `x = x` |
| `dce` | удаление инструкций без побочных эффектов, результат которых не используется (по живости на выходе блока), и недостижимых блоков |

Проходы выполняются по кругу до неподвижной точки. Деление на ноль и чтение
`a[i]` (проверка границ) считаются операциями с исключением: они не
сворачиваются и не удаляются как мёртвые (деление удаляется только при
ненулевой константе-делителе).

## Формат IR

Операнды это переменные, временные `%tN` и целые константы; инструкции
`mov copy bin neg not aload astore len call jump br ret`; блок заканчивается
одним терминатором. 

Пример (`demo` из `samples/opt_demo.funny`, `r = x * 1 + b - 0` и т.п.):

```
до оптимизаций                       после (all)
entry:                               entry:
    %t1 = 3 * 4                          %t2 = x
    a = 2 + %t1                          %t3 = %t2 + 14
    b = a + 0                            r = %t3
    dead = x * 10                        ret r
    %t2 = x * 1
    %t3 = %t2 + b
    r = %t3 - 0
    %t4 = 0 * x
    r = r + %t4
    ret r
```

## Что переводится в IR

Присваивания (`x = e`, `a[i] = v`, `x, y = f(...)`), `if`/`else`, `while`,
блоки, арифметика, сравнения, `not`, вызовы, `length`, `a[i]`. Логические
`and`/`or`/`->` вычисляются лениво через переходы. В конце функции `ret` со
всеми `returns`-переменными.

Не переводятся `requires`, `ensures`, `invariant`, `assert`, `assume`, формулы
и кванторы: это спецификации для верификации без исполняемой семантики.

## Выходные данные

* текст: IR до и после (с комментарием `; -> следующие блоки`), таблица метрик;
* JSON (`--json` или `output/ir/NAME/ir.json`): IR до/после, метрики, граф конфликтов и раскраска;
* DOT: CFG до/после и граф конфликтов до/после (`--dot DIR` или `output/ir/NAME/`);
* `output/ir/NAME/`: `before.ir`, `after.ir`, `ir.json`, `metrics.txt`,
  `interference.txt`, `FUNC.cfg.{before,after}.dot`, `FUNC.interference.{before,after}.dot`.

## Метрики

Для каждой функции до и после оптимизаций: число блоков, инструкций,
временных (реально используемых) и цветов в раскраске. Пример
(`output/ir/opt_demo/metrics.txt`):

```
функция             блоков    инструкций     временных      цветов
                  до→после      до→после      до→после    до→после
demo                 1 → 1        10 → 4         4 → 2       1 → 1
poly                 1 → 1         9 → 9         7 → 7       3 → 3
constCond            4 → 3         7 → 4         1 → 0       1 → 0
```

## Граф конфликтов и раскраска

Вершины это временные. Временные конфликтуют, если одна определяется в момент,
когда другая жива; живость считается по всему CFG. Раскраска жадная: вершины
по убыванию степени, каждой наименьший свободный цвет. Временные разных типов
(`int`, `int[]`) цвет не делят (слоты JVM типизированы). Число цветов это
количество слотов, которого достаточно для временных функции (раскраска жадная,
поэтому оно не обязательно минимально возможное).

## Тесты

`python3 src/main.py test` (44 теста), виды (`tests/ir_tests.json`):

| Вид | Что проверяет | Кол-во |
|---|---|---|
| `run` | функция выполняется **до** и **после** оптимизаций при шести режимах флагов; результаты (или ошибки времени выполнения) совпадают с независимым эталоном | 26 |
| `ir` | точный текст IR до и после | 8 |
| `cfg` | блоки и рёбра CFG | 3 |
| `metrics` | число блоков, инструкций, временных и цветов до/после | 4 |
| `flags` | число инструкций при каждом режиме флагов | 1 |
| `fuzz` | 2 × 120 случайных программ: результаты до и после совпадают на сетке из 27 входов при шести режимах (всего 38 880 сравнений) | 2 |

Для каждого теста дополнительно проверяется: IR проходит валидацию (структура
блоков, имена, типы операндов), раскраска корректна (соседи окрашены по-разному,
типы не смешаны), оптимизация не увеличивает число инструкций.

Регрессия предыдущих этапов остаётся зелёной: лексер 34, парсер 32,
семантика 56.
