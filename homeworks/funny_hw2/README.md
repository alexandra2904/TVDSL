## Разбор произвольного текста

```bash
python3 src/main.py ast "function id(x: int) returns r: int { r = x; }"

# полное дерево в JSON (можно перенаправить в файл)
python3 src/main.py ast "function id(x: int) returns r: int { r = x; }" --json > out.json

# разбор файла с исходником на Funny
python3 src/main.py ast "$(cat program.funny)" --json
```

При синтаксической ошибке печатается `PARSE ERROR [строка:столбец]: сообщение`
для каждой найденной ошибки (их может быть несколько), и в конце код возврата 1. При отсутствии ошибок -- 0.

## Формат AST

Каждый узел сериализуется как `{"node": "ИмяКласса", ...поля...}`,
поля рекурсивно разворачиваются. У каждого узла
есть поле `"pos"` -- символьное смещение в исходном тексте (то же, что
`Token.start` у лексера), на нём строятся сообщения об ошибках.

Пример для `r = x + 1;`:
```json
{
  "node": "SimpleAssign",
  "target": "r",
  "value": {
    "node": "BinOp", "op": "+",
    "left": {"node": "Var", "name": "x", "pos": 4},
    "right": {"node": "IntLiteral", "value": 1, "pos": 8},
    "pos": 6
  },
  "pos": 0
}
```

Полный список типов узлов -- в `src/ast_nodes.py`: `VariableDef`,
`LocalVarDef`, `IntLiteral`, `BoolLiteral`, `Var`, `ArrayAccess`, `Call`,
`UnaryOp`, `BinOp`, `Quantifier` (выражения); `Block`, `If`, `While`,
`Assert`, `Assume`, `SimpleAssign`, `ArrayAssign`, `TupleAssign`
(операторы); `FunctionDef`, `FormulaDef`, `Module` (верхний уровень).

## Обработка ошибок: паникующий режим (panic mode)

Парсер не останавливается на первой ошибке. При сбое:

1. Ошибка (сообщение + позиция) запоминается в список `errors`.
2. Токены пропускаются до ближайшей "точки синхронизации":
   - **внутри блока операторов** -- до `;` или `}` (включая её же пропуск,
     если это `;`; `}` оставляется, чтобы блок корректно закрылся);
   - **на верхнем уровне модуля** -- с отслеживанием глубины `(`/`{`, пока
     не выйдем на глубину 0 и не увидим `IDENT` (вероятное начало
     следующей функции/формулы) или не кончится вход.
3. Разбор продолжается с этой точки, поэтому за один прогон можно
   получить сразу несколько сообщений об ошибках, а не только первое.

Гарантия отсутствия зацикливания: оба механизма восстановления всегда
продвигают позицию хотя бы на один токен за итерацию, даже если ни один
"правильный" путь дальше не виден (тест `"garbage tokens... must not
hang"` в `parser_tests.json` -- вход без единого `IDENT` корректно
завершает разбор с одной ошибкой, а не зависает).

## Тестирование

`tests/parser_tests.json`, три вида проверки (поле `kind`):

- **`expr`** -- разобрать строку как одно выражение, сравнить AST со
  `expected_ast` (snapshot без поля `pos`, чтобы тесты не ломались от
  косметических изменений пробелов). Сюда вынесены все проверки
  приоритета/ассоциативности операторов (`1+2*3`, `a-b-c`, `a->b->c`,
  `not a and b or c`, ...).
- **`module`** -- разобрать строку как целый модуль, ожидается, что
  ошибок НЕ будет, и AST совпадёт со snapshot. Сюда входят функции с
  `if`/`while`/`assert`/`assume`, формулы, кванторы, `length(...)`,
  цепочка `a[i][j]=v`, tuple-присваивание `x,y=f(...)`.
- **`error`** -- ожидается хотя бы одна ошибка: незакрытая скобка,
  лишние токены после валидной программы, двойной оператор (`**`),
  пустой ввод, пропущенная `;`, отсутствие обязательного `returns`,
  мусор без единого `IDENT` (проверка отсутствия зацикливания),
  "висячий" бинарный оператор без правого операнда, незакрытая `[`,
  квантор без `|`.

Отдельно `python3 src/main.py lextest` прогоняет все 34 теста лексера
из HW1 на этой же (скопированной без изменений) базе -- регрессия
подтверждает, что интеграция с HW1 ничего не сломала.
